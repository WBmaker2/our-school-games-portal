# 👻 우리학교 영혼 대결 (The Great Ghoul Duel) - 시스템 아키텍처 및 확장 규격

본 문서는 구글 두들의 전설적인 4 vs 4 실시간 팀 대항 액션 게임인 **「우리학교 영혼 대결」**의 기술 구조 및 향후 확장 로드맵을 정리한 아키텍처 문서입니다.

---

## 1. 1단계 아키텍처 (현재 구현: 고성능 클라이언트 & 7마리 스마트 AI 봇)

별도의 외부 백엔드 서버나 네트워크 지연 시간(0ms) 없이 브라우저 60fps 캔버스 환경에서 4 vs 4 대전을 즉시 즐길 수 있도록 완벽하게 구현되었습니다.

### 핵심 모듈 구성
* **`ghoulDuelConstants.js`**: 대저택 맵 충돌 박스, 팀 컬러/기지 좌표, 유령 캐릭터 8종, 파워업 및 난이도 설정
* **`ghoulDuelLogic.js`**:
  * **2D 캔버스 렌더러**: 조명 글로우, 다채로운 8종 캐릭터, 역기구학 꼬리, 대저택 타일 및 미니맵 레이더
  * **역기구학 꼬리 물리**: 뱀 형태의 자연스러운 체인 추적 및 원-선분 인터셉트 꼬리 끊기(Steal) 판정
  * **FSM 기반 7마리 스마트 AI**: `SEARCH`(영혼 탐색), `RETURN`(기지 복귀), `HUNT_STEAL`(꼬리 기습 공격), `FLEE`(위험 도주)
* **`ghoulDuelAudio.js`**: Web Audio API 무손실 절차적 사운드 신디사이저 (영혼 획득, 꼬리 절단, 기지 득점 화음, 카운트다운, 빅토리 팡파르)
* **`GhoulDuelGame.jsx`**: React UI 레이어, 실시간 팀 점수 게이지 바, 모바일 가상 조이스틱, 명예의 전당 연동 (`score > 100`)

## 2. 2단계 확장 규격 (향후 친구 초대 P2P WebRTC 방 코드 멀티플레이)

향후 친구들과 별도의 유료 서버 비용 없이 실시간으로 대전하기 위한 P2P 연동 인터페이스 설계안입니다.

### 네트워크 구조 (Host-Authoritative P2P via WebRTC DataChannel)
```text
[ 플레이어 A (방장 / 호스트) ]
  ├── 게임 물리 엔진 & 충돌 판정 (Authoritative Host)
  ├── P2P DataChannel 1 ──> [ 플레이어 B (친구 1) ]
  ├── P2P DataChannel 2 ──> [ 플레이어 C (친구 2) ]
  └── 빈 슬롯은 스마트 AI 봇이 자동으로 대체
```

1. **룸 코드 생성 (Signaling)**:
   - 무료 공용 STUN 및 PeerJS / Trystero 브로커를 통해 4자리 영문 룸 코드(예: `GHOUL-88`) 생성.
2. **동기화 프로토콜**:
   - **클라이언트 -> 호스트**: 입력 벡터 `{ vx, vy }` 초당 30회 전송
   - **호스트 -> 클라이언트**: 8마리 유령 좌표, 꼬리 길이, 영혼 위치, 점수 패킷 브로드캐스트
3. **지연 보상**:
   - 클라이언트 측 보간(Interpolation)을 통해 핑 50~100ms 환경에서도 부드러운 움직임 보장.
